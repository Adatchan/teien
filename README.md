# 定演チケットシステム（teien-ticket）

岡大グリーの定期演奏会のための、**取り置きチケットの受け渡し**と**当日券の販売**を兼ねたシステムです。
模擬店のレジ・キッチンのシステム（[mogiten](https://github.com/adatchan/mogiten)）をもとに作りました。
**Cloudflare Workers + D1**（無料プラン）で動きます。

本番: **https://teien-ticket.adachiyuki0409.workers.dev**（D1 のデータベース `teien-ticket` はアジア太平洋に置いています）

| 画面 | URL | 認証 | 使い方 |
|---|---|---|---|
| 入口 | `/` | 不要 | 各画面へのリンクだけ |
| 受付（取り置き） | `/reception` | 名前＋レジ用パスワード（3日間有効） | 取り置きのカードを名前で探し、渡したら**右へスワイプ** |
| レジ（当日券） | `/admin` | 担当者名＋レジ用パスワード（3日間有効） | 当日券を売って記録する。**今の売上**もここで見る |
| 管理画面 | `/master` | マスターパスワード（12時間有効） | 券種・価格、**取り置きの CSV の取り込み**、**ウェブ予約の設定**、**売上の CSV** |
| ウェブ予約（団員用） | `/order` | **メールアドレス＋取り置き専用パスワード** | 団員が知り合いの分の取り置きを予約。**開場時刻まで**受け付ける |

ダッシュボードはありません（売上はレジ画面と管理画面で見ます）。模擬店システムの「容器代」「味」「キッチン」はありません。

## 当日の流れ

**取り置き（受付）**

1. 事前に、取り置きの一覧を所定の様式の CSV にまとめ、管理画面の「取り置き」で取り込む（[様式](docs/reservation-csv.md)）
2. 受付のスマホ・タブレットで `/reception` を開く。取り置きが 1 件ずつ**カード**で並ぶ（キッチン画面と同じ形）
3. お客さんの名前・フリガナ・番号を上の欄に入れてカードを探す（ひらがなとカタカナは区別しない）
4. カードのオレンジの「当日 ¥2,800 受け取る」は、代金を受け取ってから渡す。緑の「支払済み」は渡すだけ
5. 渡したらカードを**右へスワイプ**（またはタップ）→ 打ち消し線が引かれ、時刻と渡した人が記録される。左へスワイプ・もう一度タップで戻す

**ウェブ予約（団員用・開場時刻まで）**

取り置きは、出演者（団員）が知り合いにチケットを事前に渡せないときに使う手段です。

1. 管理画面の「公演の設定」で**開場時刻**（締め切り）を入れ、「ウェブ予約（取り置き）」で受け付けるにチェック・1 組あたりの上限枚数・**取り置き専用パスワード**を決めて保存
2. 予約ページ `/order` の URL とパスワードを団員に伝える
3. 団員は**メールアドレスとパスワード**で認証 → **団員氏名** → 当日来るお客さん **1 組ごとのカード**（代表の方の氏名を**カタカナのセイ・メイ**で。ひらがな・半角カナは自動でカタカナに直し、漢字・英字・記号は受け付けない／券種と枚数／備考）を「＋ 組を追加」で必要なだけ足して、まとめて予約。予約番号は 1 組ごとに **W1, W2…**（1 回に 10 組まで）
4. 代金は**いつも終演後に団員からまとめて回収**（受付ではお客さんから受け取らない）
5. 予約後に控えを表示。「控えをメールで送る」で団員のメールアプリから自分あてに控えを送れる（メール送信サービスを設定すれば自動でも送る。下の「控えのメールを自動で送る」）
6. 届いた予約はすぐ取り置きの一覧に入り、受付の画面に数秒で出る（青く光る）。**開場時刻を過ぎると自動で締め切り**、一覧が確定する
7. 終演後、管理画面の「**団員ごとの精算**」で団員ごとの金額を確かめ、受け取ったら「回収済みにする」

事前に CSV で取り込んだ取り置きと、ウェブ予約は同じ一覧に並びます。受付の端末は数秒ごとに一覧を読み直すので、開場までに届いた予約も受付に出ます（事前に保存した CSV やオフライン用に保存した一覧には、そのあとの予約は入っていないので、開場後に一度電波のある場所で開き直すと確実です）。

**当日券（レジ）**

1. `/admin` で券種ごとに枚数を入れる（ペア券などのセット価格は自動で一番安く組む）
2. 支払方法 → 現金ならお預かり → 確認画面で「はい（記録する）」
3. 画面のいちばん上に、**当日券の売上・取り置きの当日精算で受け取った額・その合計・受け渡しの件数**が出る（「内訳」で券種ごと・支払方法ごと）

当日券は受付には出ません（キッチン画面のようなものは不要なので、記録が残るだけです）。

## できること

**公演ごとの管理**（管理画面）
- 公演（例: 第61回定期演奏会）ごとに、券種・価格、支払方法、取り置き、当日券の会計を分けて記録する
- 新しい公演は、前の公演から券種・価格・支払方法を複製して作れる
- レジと受付で使うのは「当日に使う」公演 1 つ。切り替えるとレジは 30 秒ほど、受付は数秒で切り替わる

**券種**（模擬店システムの「商品」の設定をそのまま使う）
- 券種名・単位・枚数ごとの価格（1 枚の価格は必須。ペア券などのセット価格も登録できる）
- 「○○のセット価格に含める」で、別の券種と枚数を合わせてセット価格にできる
- 「販売中」を外すとレジに出なくなる（取り置きでは使える。招待券・前売り券など）
- 並び替え、削除（当日券の販売や取り置きで使っていない券種だけ）

**取り置き**
- 管理画面で CSV を選ぶと、**取り込む前に**件数・枚数・受付で受け取る額・1 件ずつの内容と、直すところ（行番号つき）を確認できる
- Excel で保存した Shift_JIS の CSV も、UTF-8 の CSV も読める
- 同じ番号の行は 1 件にまとめる（1 人で複数の券種）。券種名を見出しにした「横持ち」の CSV も読める
- 「追加・更新」と「この CSV に置き換える」。どちらでも、同じ番号の取り置きの**受け渡しの記録は残る**（本番中の追加・修正も可）
- 支払が「当日」の取り置きは、受付で受け取る金額をカードに出し、受け渡したら「取り置き精算」として売上に足す
- 受付の画面：検索、番号順／名前順（五十音）、「渡したものを隠す」、券種ごとの残り枚数・未収額・受取済額
- 受付は**電波がなくても**使える（最後に読んだ一覧を表示し、受け渡しの操作は端末に保存して電波が戻ったら送る）
- リハーサル用に「受け渡しの記録をすべて未に戻す」、やり直し用に「取り置きをすべて削除」。1 件ずつの削除（ウェブ予約の取り消しなど）

**ウェブ予約**（`/order`・団員用）
- メールアドレスと公演ごとの取り置き専用パスワードで認証した人だけが、券種と価格を見て予約できる（パスワードは PBKDF2 でハッシュ化して保存。間違いが続いた接続元は10分間止める）
- 団員氏名と、お客さん 1 組ごとのカード（代表の方の氏名はカタカナのセイ・メイを強制、券種と枚数、備考）。カードは追加・削除でき、まとめて 1 回で予約（1 組でも間違いがあれば 1 組も入らない）
- 代金はいつも団員から回収（画面で選ばせず、サーバーでも団員払いに固定）
- メールアドレスと団員氏名はその端末に覚えておき、続けて別のお客さんを予約できる
- 開場日時を過ぎると自動で締め切り。管理画面でいつでも止められる
- 予約できる券種は「ウェブ予約に出す」にした券種だけ（招待券などは外す）。1回の上限枚数を決められる
- 同じ予約を 2 回送っても 1 件（通信が切れて送り直したとき）。同じ接続元からは 1 時間に 20 件まで
- 予約した団員には予約番号と内容（控え）を表示し、その端末に控えと「団員が終演後に払う額の合計」を残す

**団員ごとの精算**（管理画面）
- 「代金は団員から回収」の取り置きを団員の名前ごと（全角・半角・空白の違いは同じ人）にまとめ、件数・枚数・金額・受け渡し済みの枚数を表示
- 「回収済みにする」で回収の時刻を記録（戻せる）
- **Excel**（`members.xlsx`）で書き出せる：シート「団員ごとの精算」（団員ごとの件数・枚数・回収する額・回収済み・未回収・状態を色分け、受領サインの空欄、合計は数式、A4 横で印刷）と「明細」（団員から回収する取り置きを 1 件ずつ）。CSV（`members.csv`）も
- 受付のカードには「代金は団員から回収（受け取らない）」と団員の名前が出る。受付の検索は団員の名前でもできる
- CSV を「置き換え」で取り込んでも、ウェブで受け付けた取り置きは消えない

**当日券（レジ）** — 模擬店システムのレジと同じしくみ
- 支払方法（公演ごとに選ぶ。初期は現金だけ）、お預かり・おつり、確認画面
- 最近の会計の取消／戻す、すべての会計の一覧（`/history`）
- オフライン対応（会計と取消は端末に保存して、電波が戻ったら送る。二重に記録しない）
- 管理画面で「販売終了」にすると、新しい会計を記録できなくなる（受付はそのまま使える）

**CSV**（管理画面から。項目の定義は [docs/csv-spec.md](docs/csv-spec.md)）
- 当日券の売上（手集計用・Excel 向け）、当日券の会計・明細（データ分析用）
- 取り置きの一覧と受け渡し（受け渡し済みか・受け取った額・渡した時刻と人。そのまま取り込み直せる）
- 取り置きの様式（記入例つき）

**そのほか**（模擬店システムと同じ）
- ログイン中の端末の一覧と締め出し、パスワードの変更、ログイン制限の解除、操作の記録
- 全画面に「?使い方」のヘルプ
- フォントは Noto Sans JP。デザインのきまりは [docs/design-system.md](docs/design-system.md)

## セキュリティのしくみ

- ログインに成功すると、ランダムなセッショントークンを **HttpOnly・Secure・SameSite=Strict の Cookie** に入れます。パスワードは端末に保存しません。サーバーにはトークンのハッシュだけを保存します。
- 画面から変更したパスワードは **PBKDF2（SHA-256・10万回）** でハッシュ化して D1 に保存します。一度も変更していないときは secret（`ADMIN_PASSWORD` / `MASTER_PASSWORD`）と照合します。
- **同じ接続元から10分間に5回** パスワードを間違えると、その接続元からは10分間ログインできません。
- 別のサイトからの書き込みリクエストは拒否します（Origin チェック）。
- 取り置き（お客さんの名前）は、レジ用パスワードでログインした端末でだけ見られます。受付の端末は電波がないときのために最後の一覧を保存しますが、ログインが切れると消します。

## 構成

```
public/index.html      入口
public/reception.html  受付（取り置きの受け渡し）
public/admin.html      レジ（当日券）
public/history.html    当日券の会計の一覧（レジのログインで見られる）
public/master.html     管理画面
public/order.html      ウェブ予約（お客さん向け）
public/pricing.js      料金計算（セットの組み方）。画面とサーバーで共通
public/sw.js           Service Worker（レジと受付のオフライン対応。VERSION を更新ごとに変える）
public/tokens.css      デジタル庁デザインシステムのトークン（そのまま写したもの・書き換えない）
public/app.css         全画面共通のデザイン
public/help.css, help.js  ヘルプ（使い方）ダイアログ
src/index.js           API（Cloudflare Worker）
docs/reservation-csv.md   取り置きの CSV の様式
docs/reservations-sample.csv 取り置きの CSV の見本
docs/csv-spec.md       書き出す CSV の項目定義
test/                  自動テスト（npm test）
wrangler.toml          Cloudflare の設定
```

データは Cloudflare D1（SQLite）に保存されます。テーブルは初回アクセス時に自動で作成され、空の「最初の公演」が 1 つできます。

## セットアップ（初回のみ・15分くらい）

必要なもの: Cloudflare アカウント（無料）、Node.js 18 以上が入った PC

```bash
# 1. このリポジトリを取得して依存をインストール
git clone https://github.com/Adatchan/teien.git
cd teien
npm install

# 2. Cloudflare にログイン（ブラウザが開きます）
npx wrangler login

# 3. データベースを作成
npx wrangler d1 create teien-ticket
#    → 表示された database_id を wrangler.toml の「ここに database_id を貼る」に貼り付けて保存

# 4. デプロイ
npx wrangler deploy
#    → https://teien-ticket.xxxx.workers.dev が表示されます

# 5. 初期パスワードを設定（入力を求められるので好きなパスワードを入力）
npx wrangler secret put ADMIN_PASSWORD    # レジ・受付用
npx wrangler secret put MASTER_PASSWORD   # 管理画面用
```

あとは、
1. 管理画面（`/master`）で公演を開き、名前と公演日を直す（または新しく作る）
2. 「券種・価格」で券種を登録する（例: 一般 1,500円・2枚 2,800円、学生 500円、招待 0円（販売中を外す））
3. 「取り置き」の「⬇ 様式（記入例つき）」を保存し、取り置きの一覧を書いて取り込む
4. 受付の端末で `/reception`、レジの端末で `/admin` を開いてログインしておく
5. リハーサルで受け渡しを試したら、管理画面の「受け渡しの記録をすべて未に戻す」で戻す。テストの当日券は「当日券の売上記録を全リセット」で消す

で準備完了です。

### 控えのメールを自動で送る（任意）

Cloudflare だけでは好きなアドレスにメールを送れないため、メール送信サービス [Resend](https://resend.com)（無料枠あり）を使います。設定しなければ自動では送らず、予約の画面の「控えをメールで送る」ボタン（団員のメールアプリで送る）だけになります。

1. Resend に登録し、送り主にするドメインを確認する（DNS にレコードを足す）
2. API キーを作る
3. 次の 2 つを設定する

```bash
npx wrangler secret put RESEND_API_KEY   # Resend の API キー
npx wrangler secret put MAIL_FROM        # 送り主（例: 定演チケット <ticket@example.com>）
```

送れなかったときは、管理画面の操作の記録に「控えのメールを送れませんでした」と残ります。

### コードを修正したとき

```bash
npm test
npx wrangler deploy
```

画面を変えたときは `public/sw.js` の `VERSION` も変えてください（レジと受付の端末が新しい版に切り替わります）。

## メモ

- データベース: 公演は `projects`（`order_enabled`・`open_at`・`order_max`・`order_pw_hash` がウェブ予約の設定）、券種は `products`（`web` = ウェブ予約に出す）、当日券は `sales` と `sale_items`、取り置きは `reservations`（`tickets` は券種ごとの枚数の JSON、`handed_at` / `handed_by` が受け渡しの記録、`source` は `csv` / `web`、`settle` は代金の払い方 `reception`（受付で）/ `member`（団員から）/ `paid`（済）、`member` / `email` は団員、`collected_at` は団員から回収した時刻）。「当日に使う」公演は `settings` の `active_project` です。
- 取り置きの金額は、取り込んだときの価格で保存します。あとで券種の価格を変えても、取り込み直すまで変わりません。
- 取り置きの当日精算（受付で受け取る分）は現金で受け取る想定です（支払方法は記録しません）。団員からの回収額は、レジの「受け取った額の合計」には入れず、別に表示します。
- マスターパスワードを忘れたときは `npx wrangler d1 execute teien-ticket --remote --command "DELETE FROM settings WHERE key = 'master_pw_hash'"` で初期パスワード（secret の `MASTER_PASSWORD`）に戻せます。レジ・受付用は `register_pw_hash` です。
